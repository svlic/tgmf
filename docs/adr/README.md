## 如何阅读

- **A／历史事实**：提交差异、提交正文或版本内文档直接支持。
- **B／分析**：根据变化解释收益、代价和可能动机，不冒充作者当时的理由。
- **C／待确认**：目前无法确认的背景或取舍。
- **U／用户追溯确认**：项目维护者在本次调查中补充的要求，不回填成当年文档已有的事实。来源：[调查对话](https://ampcode.com/threads/T-01a186ca-e3e7-72ed-9f84-95795461c9b8)。

“已采用”表示代码采用过／当前仍采用该方案，不表示已经独立证明效果或不存在缺陷。
“待补充”表示有实现证据，但关键业务语义或原因未确认；不是本次新批准的方案。
旧方案的废弃记录在各 ADR 的演进中，不为每个修复提交另造一份 ADR。

## 后续维护

修改决策时保留旧背景，记录替代关系；不得把“计划修复”写成“当前保证”。
未实现事项和验证方法统一放在[技术债务清单](../technical-debt.md)，避免 ADR 变成不断变化的缺陷列表。
